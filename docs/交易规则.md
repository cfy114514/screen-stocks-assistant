# 当前交易规则与限制

本页描述 v0.1.1 的实现，而非对游戏盈利机制的保证。它适用于虚拟游戏《Screen Stocks》，不是现实证券交易工具。

## 股票分工

默认排除 `$BANK` 和 `$BUBL`，由玩家自行配置游戏内自动槽位。外置程序既不对它们开仓，也不替它们平仓。其余已解锁股票可进入外置策略。不要在游戏内另建控制这些相同股票的冲突规则。

## 普通策略

- 使用最近最多15分钟的有效历史价格；要求至少3分钟跨度、60个样本，最新样本不能过期。
- 无相反方向仓位时，低于均价5%可买入，高于均价5%可做空。
- 买入侧：若剩余可买股数 × 最新价格 × 1.05 不超过现金，提交 `buymax`；否则提交现金25%的 `buypercent`。5%只是报价余量，不是服务端限价或硬性预算上限。
- 做空提交25%的 `shortpercent`。多空开仓冷却分别读取游戏导出。
- 普通多头达到均价以上5%且高于买入均价时可止盈；这不是通用多头止损规则。
- 空头回落至均价且盈利时平空，或价格较空头均价上涨15%时止损。
- 普通开仓不主动在已有同向仓位上反复加仓；事件仓位有独立逻辑。
- 平仓后，同一股票至少等90秒才能再次开仓。

## 已公告拉升事件

- 只使用本地导出的公开 `event:` / `pump` 排期。目标至少为现价两倍时识别机会。
- 离计划时间超过90分钟：建事件仓，保留约一半为底仓，另一半可按均价±5%做波段。波段卖出还要求盈利，买回要求低于此前波段卖出报价。
- **前90分钟不再提交该股的任何自动买卖指令**，包括新建仓和平仓；已提交的指令不能凭空撤销。其他股票继续交易。
- 到达计划时间后：价格达到目标95%时先平多一半；随后较“计划时间之后的高点”回撤8%，且高点至少高于买入均价20%时退出剩余仓位。
- 计划时间过去15分钟后结束事件交易。若事件没有按预期兑现，退出可能亏损。
- 买入同样采用“报价可覆盖浮筹则最大买入，否则25%分批”；实际成交成本根据确认后的持仓数量和均价记账。
- 未来公告从当前导出消失时，不把缓存当成仍有效的入场依据，暂停加仓。缓存会保留用于核对已有事件仓位。

## BASE 重置

- 有已公布且有效的重置或下跌事件时，重置/下跌前90分钟可退出多头。
- 对记录过的 BASE 重置，计划时间已到、处在其后15分钟内且价格不超过基准价125%时，可尝试一次重置扫货。
- 买入使用相同的资金充足判断；成交确认后才记为该次重置已处理。
- 未读到排期时，不会仅凭“跌到了低价”就声称发生了已知重置。普通低价买入信号仍可能独立触发。

## 执行检查

一次只允许一个待确认指令。记录先持久化，再写游戏命令文件；收到 `done` 后还需看到对应持仓数量变化。20秒内未确认会停止，保留记录，重新启动也不会盲目重发。

同股已有多头时不做空，已有空头时不买入。若同时出现双向仓位，停止等待检查。行情或价格过期时不生成新指令；未知游戏版本不启用自动交易。

游戏的百分比参数与实际成交数量还受客户端计算、浮筹、价格变化和服务器规则影响。`buymax` 也只是请求最大买入，并非保证一次扫完。游戏内交易、手动交易与外置交易的并发变化仍可能影响判断。

## 运行范围

必须保持电脑、游戏和助手运行，才能持续管理事件。网页本身不是远程托管服务；不提供离线挂机保证。模拟账户只模拟部分规则，未计滑点、股息等，不能用作实际策略盈利证明。
